# 수동 테스트 체크리스트

포트폴리오 수정 후 브라우저에서 확인할 절차입니다. 아래 항목은 테스트 결과가 아닌 확인용 목록이며, 실제 확인한 항목만 체크합니다.

## 준비

- `index.html`, `style.css`, `script.js`를 같은 폴더에 둡니다.
- `index.html`을 브라우저에서 엽니다.
- 직접 파일 실행이 제한되는 환경은 Python의 `python -m http.server 8000`으로 로컬 서버를 시작하고 `http://localhost:8000`을 엽니다.
- GitHub API와 외부 글꼴 조회를 위해 인터넷에 연결합니다.
- 사용한 브라우저, 화면 너비, 확인한 브랜치 또는 커밋을 기록합니다.

## 화면과 이동

- [ ] 첫 화면에 이름, 소개, 버튼이 표시된다.
- [ ] 상단 소개·프로젝트·연락처 링크가 해당 구역으로 이동한다.
- [ ] 첫 화면의 프로젝트 보기·연락하기 버튼이 해당 구역으로 이동한다.
- [ ] 스크롤 시 구역 내용이 표시되고 빈 상태로 남지 않는다.
- [ ] 배경 애니메이션이 표시되며 주요 내용을 읽는 데 방해되지 않는다.

## 작은 화면

개발자 도구의 기기 화면 모드 또는 브라우저 창 크기 조절로 확인합니다.

- [ ] 320px, 375px, 768px 너비에서 가로 넘침이나 문구 잘림이 있는지 확인한다.
- [ ] 작은 화면에서 메뉴 버튼으로 메뉴를 열고 다시 닫을 수 있다.
- [ ] 메뉴 항목 클릭 후 메뉴 상태와 이동 결과를 확인한다.
- [ ] 메뉴를 연 채 화면을 데스크톱 크기로 넓혔을 때 배치를 확인한다.
- [ ] 긴 저장소 이름과 연락처가 카드 밖으로 넘치는지 확인한다.

문제가 보이면 통과로 표시하지 않고 아래 결과 표에 기록합니다. 현재 구현에서 이미 발생하는 문제와 수정으로 새로 생긴 문제를 구분합니다.

## GitHub 프로젝트

- [ ] 조회 성공 시 저장소 카드가 최대 6개 표시된다.
- [ ] 포크 저장소는 카드 목록에서 제외된다.
- [ ] 카드의 이름, 설명, 언어 및 스타 표시가 응답 데이터와 맞는다.
- [ ] 설명이 없는 저장소에는 '설명 없음'이 표시된다.
- [ ] 실제 정렬 결과와 화면의 정렬 안내 문구가 일치하는지 확인한다.
- [ ] 프로젝트 카드를 누르면 해당 저장소가 새 탭에서 열린다.
- [ ] 조회 실패 시 프로젝트 영역에 실패 안내가 표시된다.

실패 상태는 개발자 도구 Network에서 Offline을 선택하고 새로고침해 확인할 수 있습니다. 로컬 서버 페이지 자체를 불러오지 못하는 환경에서는 GitHub API 요청만 차단합니다. 확인 후 네트워크 설정을 원래대로 복구합니다.

## 링크와 키보드

- [ ] GitHub 및 Instagram 링크의 연결 대상이 올바르다.
- [ ] 전화 링크의 `tel:` 대상이 화면 표기와 일치한다. 실제 통화는 필요하지 않다.
- [ ] Tab 키로 링크·메뉴 버튼에 접근하고 Enter로 조작할 수 있다.
- [ ] 개발자 도구 Console에 새 오류가 생기지 않는다.
